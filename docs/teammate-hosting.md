# 队友试听打算放在哪

预定目标是一台长期开着的 HTTPS 服务器，让不在同一局域网的队友用手机打开页面。把运行服务的个人电脑临时打成公网隧道，不作为主要路径。

这次没有购买、没有注册云账号、没有部署，也没有打开隧道。预算、并发路数和机房位置都还没定，这里不写价格。

## 现在已经能用的

同一台电脑上的浏览器可以选 68 个场景、看通话文字、预览后保存，再下载 JSON 交给负责人。保存要明确同意，拒绝录音。这不是自动训练。

`/api/collect` 默认关闭，页面状态 `public_ready` 为 false。要同时设置 `ZHIYU_COLLECT_ENABLED=1`、至少 16 位且互不相同的 `ZHIYU_ADMIN_TOKEN` 和 `ZHIYU_SUBMIT_TOKEN`，才会打开。提交令牌只能写入。管理员令牌才能按代号查看。两个令牌相同或太短时，接口保持关闭。令牌不放进页面。

手机上的 `127.0.0.1` 指向手机自己。没有 HTTPS 时，手机浏览器通常不给麦克风。

## 还没做、所以不能说已经能公开使用

- 进程本身不提供 TLS。对外使用要在前面加反向代理终结 HTTPS，并把 WebSocket 升级转给这个进程。静态页面托管不够，因为信令和媒体在这个 Python 进程里。
- 没有账号体系，只有两把共享令牌。令牌泄漏就能代交或查看，不能当成面向公众的登录。
- 默认只有 STUN（`ICE_SERVERS`）。没有 TURN 时，对称 NAT 或严格防火墙后面的手机可能连不上语音。
- 识别、千问、语音合成都是百炼的远程接口，这台机器不跑模型，也不需要模型 GPU。并发上限取决于这台机器的 CPU、内存、带宽，以及百炼账号的限流。这些数还没测过。
- 通话进行中的事件在内存里。进程退出后，只有已经保存的 JSON 还在 `var/teammate_reviews`。
- 反向代理如果把空闲连接掐断，页面轮询会在下一次请求重试；语音通道仍取决于 WebRTC。

## 上线前要在目标机器上量的数

同时几路媒体时的 CPU、内存、带宽，以及识别连接是否在心跳超时里断开。测完再决定机器规格。这次的离线测试不能代替那些数。
